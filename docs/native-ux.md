# Native authentication flow

For sudo, the Howdy PAM module records a successful match in the DSO loaded by
that sudo process. Sudo's approval callback then supplies the resolved command and
arguments. A fixed root controller verifies the configured user and active local
Wayland session, drops privileges for the GTK layer-shell overlay, and exchanges
bounded JSON over an inherited socket. No public approval service exists.

The overlay occupies the monitor layer, requests exclusive keyboard focus, blocks
outside clicks, and follows validated colors from the active Omarchy theme. Enter
accepts the selected button, Allow once starts selected, Left/Right changes the
selection, and Escape denies. Closing or crashing the overlay denies. Missing or
oversized command details require password authentication.

Screen unlock uses a dedicated PAM service only after the compositor reports a
secure session-lock surface. A face match unlocks immediately. The stock password
and fingerprint paths in the cloned Omarchy lock service remain available.

The manager uses a fixed polkit action, but each profile or preference mutation
also requires fresh password-only PAM authentication. Root-owned settings keep
Howdy's disabled flag synchronized. Removing the last profile disables face
authentication; disabling retains profiles.
